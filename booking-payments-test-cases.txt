PREREQUISITES
--------------------------------------------------------------------------------
- npm run dev (Redis must be running for cron locks)
- Stripe CLI forwarding webhooks:
    stripe listen --forward-to localhost:5001/api/v1/stripe/webhook
  Put the CLI's whsec_... value in STRIPE_WEBHOOK_SECRET in .env, restart server.
- Checkout tester (real Stripe Elements form, confirms intents like the app):
    http://127.0.0.1:4242  (scratchpad/stripe-checkout/serve.js)
    Paste the clientSecret from the booking response, type a card, confirm.
- Test cards (typed into the form; any future expiry / CVC / postal code):
    4242 4242 4242 4242 -> always succeeds
    4000 0025 0000 3155 -> requires 3D Secure challenge
    4000 0000 0000 0341 -> vaults/attaches fine, all charges fail (debt lock test)
    4000 0000 0000 9995 -> declined immediately
- One customer account and one business account (business with active
  BusinessProfile + Stripe Connect onboarding complete).
- Time fork boundary: 96 hours (4 days) before slot start.

TC-13  CANCELLATION MATRIX                                           [PASSED]
--------------------------------------------------------------------------------
All cases driven by snapshot policy fields (refundPercentage, refundRules,
howLateCanCancel) via resolveCancellationPayment:
 a. Provider rejects (or approval expires)
    -> cancel PI / unlink pm -> paymentStatus "released".
 b. Customer cancels inside free window (refundPercentage 100)
    -> cancel PI / unlink pm -> "released". Verify PI canceled in dashboard.
 c. Customer cancels late (partial refund, e.g. refundPercentage 50)
    -> partial capture of fee = finalPrice * (100 - refundPercentage) / 100
    -> "partially_captured". Verify captured amount in dashboard.
 d. Customer cancels non-refundable (refundPercentage 0)
    -> full capture -> "captured".
 e. Provider cancels -> cancel PI / unlink pm -> "released".
 f. Vaulted-only booking (no PI yet) -> unlink pm only, nothing charged
    -> "released".
